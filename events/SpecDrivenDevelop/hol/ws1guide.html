개요 · Overview

이 과정의 흐름

같은 이커머스 앱을 두 가지 개발 방식으로 만들어 보고, Kiro의 주요 기능을 차례로 붙여 봅니다.

① Vibe Coding자연어 프롬프트만으로 이커머스 웹 앱을 빠르게 생성 (Task 5)
② Spec-Driven Development같은 프롬프트를 요구사항 → 설계 → 구현 단계로 진행해 Vibe와 비교 (Optional Task)
③ Steering프로젝트 규칙·표준을 정의해 AI가 일관되게 코드를 생성하도록 (Task 6)
④ MCP외부 MCP 서버를 연결해 Kiro가 최신 공식 문서를 참고하도록 (Task 7)
⑤ Agent Hook파일 저장 같은 이벤트가 발생하면 정해둔 작업을 자동 실행 (Task 8)
Vibe Coding vs Spec-Driven — Vibe는 대화형으로 빠르게 만들고, Spec-Driven은 문서(요구사항·설계·작업)를 거쳐 체계적으로 만듭니다. 이 과정에서 두 방식을 모두 경험하고 차이를 느껴봅니다.
Task 1

Kiro 설치

운영체제에 맞는 방법으로 Kiro IDE를 설치합니다. 설치 파일은 kiro.dev에서 내려받습니다.

시스템 요구사항 — macOS 11(Big Sur) 이상 또는 Windows 10/11(64-bit), 메모리 8GB 이상 권장, 설치·로그인에 인터넷 연결이 필요합니다.

macOS에 설치하기

1

설치 파일 내려받기

kiro.dev에 접속해 Download를 클릭하고 macOS용 파일을 내려받습니다. Apple Silicon(M1~M4)과 Intel 중 사용 중인 칩에 맞는 버전을 고르며, 보통 자동으로 선택됩니다.

※ 칩 확인: 화면 왼쪽 위 사과 메뉴 → 이 Mac에 관하여에서 "Apple M…"이면 Apple Silicon, "Intel"이면 Intel입니다.

2

설치(.dmg 열기)

내려받은 .dmg 파일을 더블클릭해 엽니다. 나타난 창에서 Kiro 아이콘을 Applications(응용 프로그램) 폴더로 드래그합니다.

3

첫 실행 — 보안 경고 해제

Launchpad 또는 응용 프로그램 폴더에서 Kiro를 실행합니다. 처음 실행 시 "확인되지 않은 개발자" 경고가 뜨면:

  • Kiro 아이콘을 우클릭(또는 Control+클릭) → 열기를 선택하고 다시 열기를 누릅니다.
  • 그래도 막히면 시스템 설정 → 개인정보 보호 및 보안으로 가서 하단의 "확인 없이 열기"를 클릭합니다.
Kiro가 실행되어 로그인(sign in) 화면이 나타나면 설치가 완료된 것입니다. 로그인은 Task 2에서 진행합니다.

Windows에 설치하기

1

설치 파일 내려받기

kiro.dev에 접속해 Download를 클릭하고 Windows용 설치 파일(KiroSetup.exe)을 내려받습니다.

2

설치 관리자 실행

내려받은 KiroSetup.exe를 더블클릭해 실행합니다. "Windows의 PC 보호"(SmartScreen) 창이 뜨면 추가 정보 → 실행을 차례로 클릭합니다. 사용자 계정 컨트롤(UAC) 창에서는 예를 누릅니다.

3

설치 마법사 진행

안내에 따라 설치를 진행합니다. 다음 옵션을 체크하면 편리합니다:

  • 라이선스 계약 동의 후 다음
  • 설치 경로는 기본값 권장
  • "Add to PATH"(PATH에 추가) 체크 — 터미널에서 kiro 명령 사용 가능
  • 바탕화면 아이콘 생성 체크(선택)
4

설치 완료 및 실행

설치가 끝나면 Finish를 눌러 Kiro를 실행합니다. 시작 메뉴나 바탕화면 아이콘으로도 실행할 수 있습니다.

Kiro가 실행되어 로그인(sign in) 화면이 나타나면 설치가 완료된 것입니다. 로그인은 Task 2에서 진행합니다.

원하는 로그인 방법 버튼을 클릭합니다.

2

Task 4

실습 환경 준비

폴더를 Kiro로 열고, 터미널 위치를 확인한 뒤, 필요한 도구(Node·Python·uv)를 설치합니다.

4.1 폴더 열기 — File → Open Folder

  1. Kiro 상단 메뉴에서 File → Open Folder를 선택합니다.
  2. 방금 만든 kiro-workshop 폴더를 선택해 엽니다.

4.2 터미널 열고 현재 위치 확인

  1. Kiro 상단 메뉴에서 Terminal → New Terminal을 선택해 터미널을 엽니다.
  2. 아래 명령으로 현재 위치가 kiro-workshop 폴더인지 확인합니다.
macOSLinux
pwd
Windows (PowerShell)
pwd
# 또는 명령 프롬프트(cmd)
cd
출력 경로가 ...\kiro-workshop(Windows) 또는 .../kiro-workshop(macOS·Linux)로 끝나면 올바른 위치입니다.

4.3 필요한 도구 설치 — Node · Python · uv

  • Node.js 18.x 이상 — 이커머스 애플리케이션의 프론트엔드·백엔드 실행
  • Python 3.8 이상 — 개발 도구 (MCP 서버 실행 등)
  • uv — 고속 Python 패키지 관리자 (MCP 서버 실행)

Linux (Debian·Ubuntu)

적용 후 새 터미널을 열면 반영됩니다.

Task 5

Vibe Coding으로 이커머스 웹 애플리케이션 만들기

Kiro의 Vibe Coding 기능으로, 자연어 프롬프트만으로 완전한 이커머스 웹사이트를 빠르게 구축합니다. 이 앱이 이후 Steering·Spec-Driven 실습의 바탕이 됩니다.

무엇을 만드나요?

3-tier 아키텍처React 프론트 · Node.js 백엔드 · SQL DB
상품·장바구니·결제홈·상품·장바구니·결제(모의) 페이지

5.1 Kiro 대화창에 다음 프롬프트 입력

Kiro 채팅 입력창에 아래 프롬프트를 붙여넣고 보냅니다. Kiro가 요구사항을 해석해 kiro-workshop 폴더 안에 애플리케이션 전체를 생성합니다.

▶ Kiro에 입력 (한국어)
세 개의 웹 페이지로 구성된 간단한 이커머스 웹사이트를 만들어줘. 다음을 포함해줘: 1. 홈 페이지: 20개의 샘플 상품 목록 (상품 사진은 이모지로 대체) 2. 상품 페이지: 상품 설명, 가격, 수량, 장바구니 담기 버튼, 그리고 샘플 사용자 리뷰 3. 장바구니 페이지: 구매할 상품 목록, 총 결제 금액, 그리고 수량 변경·항목 삭제 같은 동작 버튼 4. 결제 페이지: 장바구니 내용 기반 주문 요약, 배송 정보 입력, 결제 수단 선택, 주문 확정 버튼, 그리고 주문 완료(주문번호 표시) 화면 (실제 결제사 연동 없이 모의(mock) 결제로 처리하고, 확정 시 주문을 저장한다) 웹 애플리케이션은 3-tier 아키텍처를 기반으로 해줘: - UI 렌더링을 담당하는 React 기반 프론트엔드 - 장바구니 담기·삭제, 결제·주문 처리 등 애플리케이션 로직을 담당하는 Node.js 기반 백엔드 - 상품, 장바구니 항목, 주문 내역을 저장하는 SQL 기반 데이터베이스 [문서 작성 규칙] - README 등 생성하는 모든 문서 파일은 한국어로 작성해줘. - 코드 주석도 한국어로 작성해줘.
생성에는 수 분이 걸릴 수 있습니다. 중간에 승인·실행을 묻는 창이 뜨면 안내에 따라 허용합니다.

5.3 애플리케이션 테스트

  • 상품 둘러보기 — 홈 페이지에서 여러 상품을 클릭해 봅니다.
  • 장바구니 담기 — 여러 상품을 장바구니에 담습니다.
  • 장바구니 보기·수정 — 수량 변경·항목 삭제를 테스트합니다.
  • 결제 — 결제 페이지에서 주문 확정 → 주문 완료 화면까지 확인합니다.
기능이 제대로 동작하지 않으면 문제 상황을 그대로 한국어 프롬프트로 적어 Kiro에게 보내면 디버깅해 줍니다. 예: "홈 페이지에 상품이 하나도 표시되지 않아."
중요 — 앱을 중지하지 말고 그대로 두세요. 다음 Optional Task와 Task 6~8은 같은 kiro-workshop 폴더(이 앱)에서 이어서 진행합니다. 새 폴더를 만들지 않습니다.
Optional Task

Spec-Driven으로 이커머스 웹 애플리케이션 만들기

Task 5와 같은 프롬프트를 이번에는 Spec-Driven Development(명세 기반 개발)로 진행합니다. 대화형인 Vibe Coding과 달리, 요구사항 → 설계 → 구현의 체계적 단계(문서 기반)를 거칩니다. 같은 요구사항을 두 방식으로 만들어 보면서 차이를 직접 비교합니다.

선택 실습 — 시간이 부족하면 이 Task를 건너뛰고 Task 6으로 넘어가도 됩니다. 같은 kiro-workshop 폴더에서 진행하며, 구현 단계에서 Task 5에서 만든 코드가 수정되거나 다시 생성될 수 있습니다.

O.1 Spec 에이전트 선택 + 요구사항 입력

Kiro 채팅 패널에서 새 세션을 열고, 에이전트 선택기에서 Spec 에이전트를 선택한 뒤 Task 5.1과 같은 프롬프트를 보냅니다.

EARS 표기법이란?

EARS(Easy Approach to Requirements Syntax, 이어스)는 요구사항을 모호하지 않게 적기 위한 쉬운 문장 틀입니다. "시스템은 ~해야 한다(shall)"를 기본으로, 상황 키워드(WHEN·WHILE·IF·WHERE)를 앞에 붙여 언제·어떤 조건에서 무엇을 해야 하는지 분명히 합니다.

기본 (Ubiquitous)항상 지켜야 하는 규칙
“시스템은 모든 가격을 원화로 표시해야 한다.”
WHEN (이벤트)어떤 일이 일어났을 때
“WHEN 사용자가 장바구니 담기 버튼을 누르면, 시스템은 선택한 수량만큼 상품을 장바구니에 추가해야 한다.”
WHILE (상태)특정 상태가 지속되는 동안
“WHILE 장바구니가 비어 있는 동안, 시스템은 결제 버튼을 비활성화해야 한다.”
IF…THEN (예외)예외 상황 처리
“IF 배송 정보가 비어 있으면 THEN 시스템은 주문 확정을 막고 입력을 안내해야 한다.”
WHERE (선택)특정 기능이 포함된 경우에만
“WHERE 리뷰 기능이 켜져 있으면, 시스템은 상품 페이지에 리뷰를 표시해야 한다.”
생성된 requirements.md를 검토·수정하고 Move to design phase(설계 단계로 이동)를 클릭합니다. design.md를 검토·수정하고 Move to implementation plan(구현 계획으로 이동)을 클릭합니다.

# 개발 표준 (Development Standards)

## 코드 스타일
- 모든 코드에는 한글 주석을 단다.
- 함수·변수명은 영문 카멜케이스로, 의미가 드러나게 작성한다.
- 결론(핵심 로직)을 먼저, 세부 구현은 뒤에 배치한다.

## 아키텍처 원칙
- 3-tier 구조(프론트엔드 / 백엔드 / 데이터베이스)를 유지한다.
- 프론트엔드는 UI 렌더링만, 비즈니스 로직은 백엔드에 둔다.

## API 설계
- RESTful 네이밍을 따른다 (명사 복수형: /products, /cart).
- 모든 응답은 일관된 JSON 형식을 사용한다.
- 오류는 적절한 HTTP 상태 코드와 메시지로 반환한다.

## 보안
- 개인정보(이름·전화번호 등)는 로그에 남기지 않는다.
- AWS 자격 증명·API 키는 코드에 하드코딩하지 않고 환경변수(.env)로 관리한다.
- .env 파일은 git에 커밋하지 않는다 (.gitignore에 추가).

## 테스트
- 핵심 기능(장바구니 담기·삭제, 주문 확정)은 수동 테스트로 확인한다.

# React·Node.js 모범 사례 (Best Practices)

## 프론트엔드 (React)
- 화면은 재사용할 수 있는 함수형 컴포넌트로 나눈다 (예: ProductCard, CartItem).

## 백엔드 (Node.js)
- Express로 REST API를 구성하고, 라우트는 기능별 파일로 나눈다 (products, cart, orders).

Task 7

MCP 서버 연결하기

MCP(Model Context Protocol)는 Kiro가 외부 서버의 전문 도구·최신 문서에 표준 방식으로 접근하게 해 줍니다. 학습 데이터에만 의존하지 않고, 최신 공식 문서·API를 실시간으로 참조해 더 정확한 코드를 생성합니다.

이 Task에서는 AWS Knowledge MCP와 AWS Documentation MCP 두 서버를 Kiro에 연결하고 테스트합니다.

7.1 사전 준비 — uv 확인

로컬 MCP 서버는 uv/uvx로 실행됩니다. Task 4.3에서 설치했다면 준비된 것입니다.

공통
uv --version

설치가 안 되어 있으면:

Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
macOSLinux
curl -LsSf https://astral.sh/uv/install.sh | sh
⚠️ uv 명령을 찾을 수 없다면 설치 후 Kiro IDE를 재시작하세요(PATH 갱신).

7.2 Kiro에 MCP 서버 추가

활동 바의 Kiro 아이콘을 클릭합니다. MCP SERVERS 섹션에서 Open MCP Config를 클릭하고 Workspace를 선택하면 프로젝트 폴더의 .kiro/settings/mcp.json이 열립니다. 아래 두 서버를 등록합니다.

.kiro/settings/mcp.json
{
  "mcpServers": {
    "aws-knowledge": {
      "url": "https://knowledge-mcp.global.api.aws",
      "disabled": false,
      "autoApprove": []
    },
    "aws-documentation": {
      "command": "uvx",
      "args": ["awslabs.aws-documentation-mcp-server@latest"],
      "env": { "FASTMCP_LOG_LEVEL": "ERROR" },
      "disabled": false,
      "autoApprove": []
    }
  }
}
두 가지 연결 방식 — aws-knowledge는 원격(Streamable HTTP)이라 URL 한 줄로 연결(설치·자격 증명 불필요). aws-documentation은 로컬(stdio)이라 uvx가 실행 방법(command·args)으로 띄웁니다. 둘 다 자격 증명이 필요 없습니다.

7.3 연결 확인 및 테스트

  1. mcp.json을 저장하면 Kiro가 서버를 자동으로 다시 불러옵니다(또는 MCP Servers 패널에서 Refresh).
  2. MCP SERVERS 패널에서 aws-knowledge·aws-documentation이 Connected ✅ 상태인지 확인합니다.
  3. 각 서버를 펼치면 제공 도구(문서 검색·읽기·추천 등)가 보입니다.
두 서버 모두 Connected면 성공입니다. 로컬 서버는 처음 실행 시 uvx가 패키지를 내려받느라 수십 초 걸릴 수 있습니다.

아래처럼 요청하면 Kiro가 MCP로 공식 문서를 조회한 뒤 답합니다.

Agent Hook은 두 단계로 동작합니다:

  1. 이벤트 감지(Event Detection) — IDE에서 특정 이벤트를 감시합니다.
  2. 자동 실행(Automated Action) — 이벤트가 발생하면 파일을 저장하거나 정해둔 에이전트 프롬프트를 실행합니다.
Kiro 채팅 패널에서 Hook이 README.md와 Task 6에서 만든 steering 파일(product.md·tech.md·structure.md)을 갱신하는 과정을 확인할 수 있습니다. 파일을 열어 문서가 어떻게 바뀌었는지 검토하세요.

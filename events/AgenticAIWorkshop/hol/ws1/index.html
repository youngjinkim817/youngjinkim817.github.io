Task 1

작업 폴더 생성 — kiro-vibe

실습에 사용할 빈 작업 폴더 kiro-vibe를 만듭니다. 원하는 위치(예: 홈 디렉터리나 바탕화면)에 생성하세요.

macOSLinux
# 홈 디렉터리에 생성하는 예시
mkdir ~/kiro-vibe
Windows (PowerShell)
# 현재 위치에 생성하는 예시
mkdir kiro-vibe
폴더는 Kiro IDE 안에서 직접 만들 필요는 없습니다. 파인더/탐색기에서 만들어도 되고, 위 명령으로 만들어도 됩니다. 중요한 것은 비어 있는 폴더라는 점입니다.

  2. 아래 명령으로 현재 디렉터리 위치가 kiro-vibe 폴더인지 확인합니다.

Task 4

실습 환경 준비하기

실습을 진행하려면 아래 구성 요소를 설치·설정해야 합니다.

  • Node.js 18.x 이상 — 이커머스 애플리케이션의 프론트엔드·백엔드 실행
  • Python 3.8 이상 — 개발 도구 및 백엔드 연동
  • uv — MCP 서버용 고속 Python 패키지 관리자

4.1 Node.js 설치

Node.js는 이커머스 애플리케이션의 백엔드·프론트엔드 실행에 필요합니다. nodejs.org에서 LTS 버전(18.x 이상 권장)을 내려받아 설치하거나, 아래 명령으로 설치합니다.

macOS (Homebrew)
brew install node
Linux (Debian·Ubuntu)
# NodeSource LTS 저장소를 통해 설치(권장)
curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt install -y nodejs
# 또는 배포판 기본 패키지
sudo apt install -y nodejs npm
Windows는 nodejs.org에서 받은 .msi 설치 파일을 실행해 마법사 안내를 따릅니다.

설치 확인

공통
node --version
npm --version
두 명령 모두 버전 번호가 출력되면 정상 설치된 것입니다.

4.2 Python 설치

Python은 여러 개발 도구와 백엔드 연동에 사용됩니다. python.org에서 3.8 이상을 내려받아 설치하거나 아래 명령으로 설치합니다.

macOS (Homebrew)
brew install python
Linux (Debian·Ubuntu)
sudo apt install python3 python3-pip python-is-python3
Windows: 설치 프로그램 실행 시 "Add Python to PATH" 체크박스를 반드시 선택하세요. 그래야 터미널에서 python 명령을 쓸 수 있습니다.

설치 확인

공통
python --version
pip --version
macOS 참고 — python·pip는 안 되고 python3·pip3만 된다면, 셸 설정 파일에 별칭(alias)을 추가하세요.
macOS (zsh)
echo 'alias python="python3"' >> ~/.zshrc
echo 'alias pip="pip3"' >> ~/.zshrc
적용 후 현재 터미널 창을 닫고 새 터미널을 열면 별칭이 반영됩니다.

4.3 uv 설치

uv는 빠른 Python 패키지 설치·의존성 관리 도구로, Kiro가 Python 의존성과 MCP 서버를 관리할 때 사용합니다.

Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
macOSLinux
curl -LsSf https://astral.sh/uv/install.sh | sh
대안 (pip)
pip install uv

설치 확인

공통
uv --version
⚠️ uv 명령을 찾을 수 없다면, 현재 터미널 창을 닫고 새 터미널을 연 뒤 다시 확인하세요(PATH 갱신 필요).
Lab 5

Vibe Coding으로 이커머스 웹 애플리케이션 만들기

이 랩에서는 Kiro의 Vibe Coding 기능을 사용해, 자연어 프롬프트만으로 완전한 이커머스 웹사이트를 빠르게 구축합니다.

Vibe Coding이란?

Vibe Coding은 프로젝트 요구사항을 해석해 프론트엔드·백엔드·데이터베이스를 포함한 전체 애플리케이션 아키텍처를 자동 생성하는 Kiro의 AI 개발 모드입니다. 단순한 코드 생성 수준을 넘어, 비즈니스 로직·사용자 경험 패턴·기술 모범 사례까지 이해해 구현합니다.

무엇을 만드나요?

3-tier 아키텍처현대적 구조의 이커머스 웹 애플리케이션
React 프론트엔드반응형 UI와 인터랙티브 컴포넌트
Node.js 백엔드RESTful API와 비즈니스 로직
SQL 데이터베이스스키마 설계와 데이터 관계
완전한 사용자 흐름상품 둘러보기부터 장바구니 관리까지

5.1 Kiro 대화창에 다음 프롬프트 입력

Kiro 채팅 입력창에 아래 프롬프트를 붙여넣고 보냅니다. Kiro가 요구사항을 해석해 애플리케이션 전체를 생성합니다.

▶ Kiro에 입력 (한국어)
세 개의 웹 페이지로 구성된 간단한 이커머스 웹사이트를 만들어줘. 다음을 포함해줘: 1. 홈 페이지: 20개의 샘플 상품 목록 (상품 사진은 이모지로 대체) 2. 상품 페이지: 상품 설명, 가격, 수량, 장바구니 담기 버튼, 그리고 샘플 사용자 리뷰 3. 장바구니 페이지: 구매할 상품 목록, 총 결제 금액, 그리고 수량 변경·항목 삭제 같은 동작 버튼 웹 애플리케이션은 3-tier 아키텍처를 기반으로 해줘: - UI 렌더링을 담당하는 React 기반 프론트엔드 - 장바구니 담기·삭제 등 애플리케이션 로직을 담당하는 Node.js 기반 백엔드 - 상품과 장바구니 항목을 저장하는 SQL 기반 데이터베이스
생성에는 수 분이 걸릴 수 있습니다. Kiro가 파일을 만들고 의존성을 설치하는 동안 진행 상황을 지켜보세요. 중간에 승인·실행을 묻는 창이 뜨면 안내에 따라 허용합니다.

5.2 애플리케이션 실행

생성이 끝나면 아래 프롬프트를 보내 이커머스 웹사이트를 실행합니다.

▶ Kiro에 입력 (한국어)
애플리케이션을 실행해줘

5.3 브라우저에서 확인

이커머스 웹사이트가 웹 브라우저에서 자동으로 열립니다. 자동으로 열리지 않으면, 아무 브라우저나 열어 React 프론트엔드 주소로 접속하세요.

브라우저 주소
http://localhost:3000
※ 포트가 3000이 아닐 수 있습니다. Kiro 출력이나 터미널에 표시된 포트 번호로 접속하세요.

5.4 애플리케이션 테스트

이커머스 웹사이트가 실행되면 핵심 기능을 하나씩 확인합니다.

  • 상품 둘러보기 — 홈 페이지를 탐색하고 여러 상품을 클릭해 봅니다.
  • 장바구니 담기 — 여러 상품을 장바구니에 담습니다.
  • 장바구니 보기 — 장바구니 페이지로 이동해 담은 항목을 확인합니다.
  • 수량 변경 — 항목 수량을 바꿔 봅니다.
  • 항목 삭제 — 항목 삭제 기능을 테스트합니다.
기능이 제대로 동작하지 않으면, 문제 상황을 그대로 프롬프트로 적어 Kiro에게 보내면 디버깅해 줍니다. 자주 발생하는 문제는 아래를 참고하세요.

Lab 6

Spec-Driven 방식으로 이커머스 웹 애플리케이션 만들기

이 랩에서는 Kiro의 Spec-Driven Development(명세 기반 개발) 기능으로 복잡한 애플리케이션을 구조적·체계적으로 구축하는 방법을 배웁니다. 대화형인 Vibe Coding과 달리, 명확한 단계와 문서를 갖춘 정식 소프트웨어 개발 수명주기(SDLC)를 따릅니다.

Kiro의 Spec-Driven Development로 다음을 할 수 있습니다:

  • EARS 표기법으로 요구사항을 사용자 스토리와 수용 기준(acceptance criteria)으로 분해
  • 시퀀스 다이어그램·아키텍처 계획을 담은 종합 설계 문서 작성
  • 개별적이고 관리 가능한 작업(task) 단위로 구현 진행 상황 추적
  • 제품·엔지니어링 팀 간 효과적인 협업
  • 개발 전 과정에 걸친 문서 유지·관리

6.1 새 작업 폴더 생성 — kiro-spec

Lab 5와 구분되도록 새로운 빈 폴더 kiro-spec을 만듭니다.

macOSLinux
mkdir ~/kiro-spec
Windows (PowerShell)
mkdir kiro-spec

6.2 폴더 열기 — File → Open Folder

Kiro 상단 메뉴에서 File → Open Folder를 선택하고 방금 만든 kiro-spec 폴더를 엽니다.

6.3 Spec 에이전트 선택

Kiro 채팅창의 빌트인 에이전트 선택기(채팅 입력창의 에이전트 이름, 예: "Default" 클릭)에서 Spec 에이전트를 선택합니다. 이렇게 하면 요구사항 → 설계 → 구현의 단계별 워크플로로 진행됩니다.

6.4 Kiro 대화창에 다음 프롬프트 입력

Lab 5와 동일한 요구사항을 입력합니다. 이번에는 Spec 에이전트가 이를 정식 명세 문서로 정리합니다.

▶ Kiro에 입력 (한국어)
세 개의 웹 페이지로 구성된 간단한 이커머스 웹사이트를 만들어줘. 다음을 포함해줘: 1. 홈 페이지: 20개의 샘플 상품 목록 (상품 사진은 이모지로 대체) 2. 상품 페이지: 상품 설명, 가격, 수량, 장바구니 담기 버튼, 그리고 샘플 사용자 리뷰 3. 장바구니 페이지: 구매할 상품 목록, 총 결제 금액, 그리고 수량 변경·항목 삭제 같은 동작 버튼 웹 애플리케이션은 3-tier 아키텍처를 기반으로 해줘: - UI 렌더링을 담당하는 React 기반 프론트엔드 - 장바구니 담기·삭제 등 애플리케이션 로직을 담당하는 Node.js 기반 백엔드 - 상품과 장바구니 항목을 저장하는 SQL 기반 데이터베이스

Kiro는 요구사항 → 설계 → 구현 3단계 워크플로를 따르는 세 가지 핵심 파일을 생성하며, 이 파일들이 각 명세의 토대가 됩니다:

requirements.md사용자 스토리와 수용 기준을 구조화된 EARS 표기법으로 기록
design.md기술 아키텍처·시퀀스 다이어그램·구현 고려사항 문서화
tasks.md개별적이고 추적 가능한 작업으로 구성된 상세 구현 계획 제공

6.5 Requirements — 요구사항 단계

SDLC 계획(Planning) 단계를 시뮬레이션합니다. 개발팀은 고객·사내외 전문가·관리자 등 여러 이해관계자로부터 요구사항을 수집해 소프트웨어 요구사항 명세 문서를 만듭니다.

EARS 표기법이란?

EARS(Easy Approach to Requirements Syntax, 이어스)는 요구사항을 모호하지 않게 적기 위한 쉬운 문장 틀입니다. "시스템은 ~해야 한다(shall)"를 기본으로, 상황을 나타내는 키워드(WHEN·WHILE·IF·WHERE)를 앞에 붙여 언제·어떤 조건에서 무엇을 해야 하는지 분명히 합니다. 자연어의 애매함을 줄여, 개발자·기획자·검증자가 같은 의미로 읽게 됩니다.

기본 (Ubiquitous)항상 지켜야 하는 규칙
“시스템은 모든 가격을 원화로 표시해야 한다.”
WHEN (이벤트)어떤 일이 일어났을 때
“WHEN 사용자가 장바구니 담기를 누르면, 시스템은 해당 상품을 장바구니에 추가해야 한다.”
WHILE (상태)특정 상태가 지속되는 동안
“WHILE 장바구니가 비어 있는 동안, 시스템은 결제 버튼을 비활성화해야 한다.”
IF…THEN (예외)원치 않는/예외 상황에 대한 처리
“IF 재고가 0이면 THEN 시스템은 품절 표시를 해야 한다.”
WHERE (선택)특정 기능이 포함된 경우에만
“WHERE 리뷰 기능이 켜져 있으면, 시스템은 상품 페이지에 리뷰를 표시해야 한다.”

※ 영어 원문에서는 shall·WHEN·IF/THEN 등을 그대로 사용합니다. Kiro가 생성한 requirements.md를 보면 이 형식으로 사용자 스토리와 수용 기준(acceptance criteria)이 적혀 있습니다.

생성된 requirements.md를 검토하고 필요하면 수정하세요. 그런 다음 Move to design phase(설계 단계로 이동)를 클릭합니다.

6.6 Design — 설계 단계

SDLC 설계(Design) 단계를 시뮬레이션합니다. 소프트웨어 엔지니어는 요구사항을 분석해 최적의 해결책을 설계합니다. 예를 들어 기존 모듈 통합, 기술 선택, 개발 도구 식별 등을 고려합니다.

생성된 design.md를 검토하고 필요하면 수정하세요. 그런 다음 Move to implementation plan(구현 계획으로 이동)을 클릭합니다.

6.7 Implementation — 구현 단계

SDLC 구현(Implement) 단계를 시뮬레이션합니다. 개발팀은 요구사항을 분석해 매일 수행할 수 있는 작은 코딩 작업으로 나누어 제품을 구현합니다.

생성된 tasks.md를 검토하고 필요하면 수정하세요. 일부 작업은 선택(optional)으로 표시됩니다(예: 단위 테스트·문서화). 핵심 기능에 먼저 집중하기 위한 것으로, 선택 작업을 그대로 두거나 전부 필수로 바꿀 수 있습니다.

작업 실행 (Task Execution)

tasks.md에서 각 작업 위의 ⚡ Start task 버튼을 눌러 작업을 하나씩 실행합니다. Kiro가 필요한 코드 변경과 명령 실행을 수행합니다. 또는 아래 프롬프트를 보내 모든 작업을 한 번에 실행할 수도 있습니다.

▶ Kiro에 입력 (한국어)
스펙의 모든 작업을 실행해줘
권장: 모든 작업을 한꺼번에 실행하기보다 작업 단위로 하나씩 실행하는 것이 더 좋은 결과를 얻습니다. 전체 작업 완료에는 약 20~30분이 걸립니다.

4.1 Node.js 설치

Node.js는 이커머스 애플리케이션의 백엔드 · 프론트엔드 실행에 필요합니다. nodejs.org에서 LTS 버전(18.x 이상 권장)을 내려받거나 아래 명령으로 설치합니다.

macOS (Homebrew)
brew install node
Linux (Debian · Ubuntu)
# NodeSource LTS 저장소를 통해 설치 (권장)
curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt install -y nodejs
Windows는 nodejs.org에서 받은 .msi 설치 파일을 실행해 마법사 안내를 따릅니다.

설치 확인

공통
node --version
npm --version
두 명령 모두 버전 번호가 출력되면 정상 설치된 것입니다.

4.2 Python 설치

Python은 여러 개발 도구와 백엔드 연동에 사용됩니다. python.org에서 3.8 이상을 내려받거나 아래 명령으로 설치합니다.

macOS (Homebrew)
brew install python
Linux (Debian · Ubuntu)
sudo apt install python3 python3-pip python-is-python3
Windows: 설치 프로그램 실행 시 "Add Python to PATH" 체크박스를 반드시 선택하세요. 그래야 터미널에서 python 명령을 쓸 수 있습니다.

설치 확인

공통
python --version
pip --version
macOS 참고 — python · pip가 아니라 python3 · pip3만 된다면 셸 설정 파일에 별칭을 추가하세요.
macOS (zsh)
echo 'alias python="python3"' >> ~/.zshrc
echo 'alias pip="pip3"' >> ~/.zshrc
적용 후 현재 터미널 창을 닫고 새 터미널을 열면 별칭이 반영됩니다.

uv는 빠른 Python 패키지 설치 · 의존성 관리 도구로, Kiro가 Python 의존성과 MCP 서버를 관리할 때 사용합니다.

Windows (PowerShell)

macOSLinux

설치 확인

공통

Vibe Coding이란?

Vibe Coding은 프로젝트 요구사항을 해석해 프론트엔드 · 백엔드 · 데이터베이스를 포함한 전체 애플리케이션 아키텍처를 자동 생성하는 Kiro의 AI 개발 모드입니다. 단순한 코드 생성 수준을 넘어, 비즈니스 로직 · 사용자 경험 패턴 · 기술 모범 사례까지 이해해 구현합니다.

무엇을 만드나요?

3-tier 아키텍처현대적 구조의 이커머스 웹 애플리케이션
React 프론트엔드반응형 UI와 인터랙티브 컴포넌트
Node.js 백엔드RESTful API와 비즈니스 로직
SQL 데이터베이스스키마 설계와 데이터 관계

▶ Kiro에 입력 (한국어)
세 개의 웹 페이지로 구성된 간단한 이커머스 웹사이트를 만들어줘. 다음을 포함해줘: 1. 홈 페이지: 20개의 샘플 상품 목록 (상품 사진은 이모지로 대체) 2. 상품 페이지: 상품 설명, 가격, 수량, 장바구니 담기 버튼, 그리고 샘플 사용자 리뷰 3. 장바구니 페이지: 구매할 상품 목록, 총 결제 금액, 그리고 수량 변경·항목 삭제 같은 동작 버튼 웹 애플리케이션은 3-tier 아키텍처를 기반으로 해줘: - UI 렌더링을 담당하는 React 기반 프론트엔드 - 장바구니 담기·삭제 등 애플리케이션 로직을 담당하는 Node.js 기반 백엔드 - 상품과 장바구니 항목을 저장하는 SQL 기반 데이터베이스

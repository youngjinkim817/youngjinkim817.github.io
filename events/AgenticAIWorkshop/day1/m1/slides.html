.kiro 디렉토리

설정의 두 스코프 — Global · Workspace

Global(전역) 또는 Workspace(워크스페이스) 단위로 설정하며, Workspace 설정이 우선합니다.

🌐 GLOBAL~/.kiro/
개인 PC 전체 설정 — 모든 Workspace 공통
~/.kiro/ (Global) ├── steering/ # 팀 표준, 보안 정책 │ ├── coding-standards.md │ └── team-conventions.md ├── settings/ │ └── mcp.json # 전역 MCP ├── agents/ └── skills/
📁 WORKSPACE<project>/.kiro/우선순위 높음
Workspace별 설정 — 팀과 Git으로 공유
<project>/.kiro/ (Workspace) ├── steering/ # 아키텍처, 컨벤션 │ ├── product.md │ ├── tech-stack.md │ └── conventions.md ├── specs/ # 요구사항/설계/태스크 ├── settings/ │ └── mcp.json # Workspace 전용 MCP ├── hooks/ ├── agents/ ├── skills/ └── powers/
08
Kiro IDE · 실행 모드

실행 모드 — Autopilot · Supervised

채팅 패널의 동작 방식 스위치 — 파일 수정 승인 방식을 선택합니다.

🚀 Autopilot — 기본

  • 파일 생성·수정을 단계 승인 없이 진행
  • 결과 확인 후 대화로 조정
  • 실습 기본 설정 — 신속한 진행
VS

🔍 Supervised — 검토형

  • 파일 수정이 포함된 턴마다 승인
  • 변경 사항을 조각 단위로 수락·거부
  • 민감한 데이터·운영 작업에 적합
⚠️ CAUTION   Autopilot에서도 명령 실행 등은 승인 창(Allow)이 별도로 표시됩니다 — 「모든 명령 허용」 설정은 사용하지 않습니다.

Vibe vs Spec · 선택

언제 Vibe, 언제 Spec

작업의 성격에 따라 두 모드를 골라 씁니다.

💬 Vibe — 빠른 탐색

  • 아이디어 프로토타이핑·간단한 작업
  • 정해진 절차 없이 대화 흐름대로
  • 혼자 빠르게 만들고 바로 확인
VS

📋 Spec — 체계적 구현

  • 복잡하거나 협업이 필요한 기능
  • 요구사항·설계를 먼저 합의
  • 유지보수·재현이 중요한 프로덕션
💡 TIP   작게 시작할 땐 Vibe, 규모가 커지면 Spec으로 — 한 프로젝트 안에서도 섞어 쓸 수 있습니다.

Steering

프로젝트 규칙
프로젝트 지식·규칙을 정의해, 세션 내내 매 대화에서 Kiro가 자동 참고하게 합니다.
동작 방식
  • 지식·규칙을 정의 → 매 대화에서 자동 참고
  • 코드·API·테스트가 팀 규칙을 따라 일관 생성
  • 포함 방식: 항상·조건부(fileMatch)·수동·자동
  • Global(~/.kiro) 또는 Workspace(.kiro) — Workspace 우선
  • 기본 3파일: product.md · tech.md · structure.md
예시
# .kiro/steering/ product.md # 제품 목적·대상 tech.md # 스택·기술 제약 structure.md # 구성·아키텍처 # 커스텀 파일 — frontmatter로 포함 방식 지정 --- inclusion: fileMatch ---

MCP

외부 도구 연동
Model Context Protocol — 에이전트가 외부 도구와 표준 방식으로 통신하는 오픈 프로토콜.
동작 방식
  • 외부 도구와 표준 방식으로 통신 (오픈 프로토콜)
  • AWS 서비스·문서 연동 (조회·관리·비용 분석)
  • Outlook·Jira 등 업무 시스템 연동
  • 셸·CLI·파일 R/W는 내장 도구 (MCP 불필요)
예시 · .kiro/settings/mcp.json
{ "mcpServers": { "aws-docs": { "command": "uvx", "args": ["awslabs.aws-documentation-mcp-server"] } } }

Agent Hook

이벤트 자동화
"파일 저장"·"도구 호출" 등 이벤트 시 에이전트에 작업을 자동 위임, 백그라운드 자율 실행.
동작 방식
  • 이벤트 시 에이전트에 작업 자동 위임
  • 백그라운드 자율 실행 — 문서·테스트·최적화 자동화
  • 사람이 매번 지시할 필요 없음
  • when(트리거) · then(위임 작업) 구조
예시 · .kiro/hooks/*.kiro.hook
{ "name": "저장 시 린트", "when": { "type": "fileEdited", "patterns": ["src/**/*.ts"] }, "then": { "type": "askAgent", "prompt": "변경 파일을 린트·수정" } }

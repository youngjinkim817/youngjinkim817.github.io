이 모듈에서는 Kiro가 무엇인지, 왜 기존 AI 코딩 도구와 다른지, 그리고 어떻게 활용하는지를 배웁니다. Kiro는 AWS에서 개발한 에이전틱 AI IDE(Agentic AI IDE)로, 단순한 코드 자동완성을 넘어 전체 개발 워크플로우를 지원합니다.

AI 개발 도구의 진화

에이전틱 AI IDE(Agentic AI IDE)는 단순한 코드 제안 도구를 넘어, 개발 프로젝트의 전체 수명 주기를 자율적으로 관리할 수 있는 도구입니다. 개발자는 "무엇을 만들 것인가"를 정의하고, AI가 "어떻게 만들 것인가"를 자율적으로 계획하고 실행합니다.

진화 단계별 특징
  • 텍스트 에디터: 개발자가 모든 코드를 직접 작성. 도구는 텍스트 편집만 지원
  • 스마트 IDE(Intelligent IDE): 자동완성(Auto-complete), 구문 강조(Syntax Highlighting), 리팩토링 지원. 하지만 AI는 없음
  • AI 코드 어시스턴트(AI Code Assistant): GitHub Copilot, Amazon Q Developer 등. AI가 코드 라인 또는 블록을 제안. 개발자가 여전히 모든 결정을 내림
  • 에이전틱 AI IDE(Agentic AI IDE): AI가 요구사항 분석→설계→구현→테스트를 자율적으로 수행. Kiro가 이 카테고리의 대표 도구
사용 사례: 개발 생산성 변화

기존 AI 어시스턴트를 사용할 때 개발자는 여전히 아키텍처 설계, 파일 구조 결정, 컴포넌트 간 연결을 직접 처리해야 했습니다. 에이전틱 AI IDE는 이러한 설계 결정까지 AI가 지원하여 프로토타입 수준의 코드가 아닌 프로덕션 수준의 코드를 훨씬 빠르게 생산할 수 있습니다.

AI 기반 개발의 어려움
⚡프로토타입은 빠르지만...

🏗️아키텍처 결정 부재
AI가 큰 그림을 그리지 못함
단편적인 코드 생성은 잘 하지만, 전체 시스템 아키텍처(데이터 흐름, 서비스 간 통신, 배포 전략)를 체계적으로 계획하지 못합니다.
👥팀 협업 어려움
AI 생성 코드의 일관성 유지 어려움
팀원마다 다른 방식으로 AI를 사용하면 코드 스타일, 구조, 네이밍 컨벤션이 제각각이 됩니다. 공유된 맥락 없이는 코드 리뷰와 통합이 어렵습니다.
AI 기반 개발의 현실적 과제

현재 AI 코딩 도구들은 빠른 프로토타입 생성에는 뛰어나지만, 프로덕션 품질(Production Quality) 코드를 지속적으로 생산하는 데는 여러 한계가 있습니다. 이 과제들을 해결하기 위해 Spec-Driven Development 방식이 등장했습니다.

주요 과제 상세
  • 프로덕션 갭(Production Gap): AI가 생성한 프로토타입은 핵심 기능만 구현. 실제 서비스를 위한 에러 처리, 보안, 성능 최적화는 추가 작업 필요
  • 컨텍스트 손실(Context Loss): 채팅 기반 AI는 긴 대화에서 앞선 결정사항을 잊음. 파일 구조와 설계 결정의 일관성이 깨짐
  • 아키텍처 결정 부재: 데이터 흐름, 서비스 통신, 배포 전략 같은 큰 그림을 AI가 스스로 계획하지 못함
  • 팀 일관성 문제: 개인별 AI 사용 방식의 차이로 코드 품질과 스타일이 불균일해짐
사용 사례: 6개월 프로젝트의 현실

스타트업 팀이 AI로 MVP를 빠르게 구축했지만, 6개월 후 기능 추가가 점점 어려워졌습니다. AI가 초기 설계를 "기억"하지 못해 새 기능 추가마다 전체 컨텍스트를 다시 설명해야 했습니다. Kiro의 Spec 파일은 이 컨텍스트를 영구적으로 저장하여 이 문제를 해결합니다.

Kiro 정의

Kiro는 AWS가 개발한 에이전틱 AI IDE(Agentic AI IDE)입니다. VS Code(Code OSS)를 기반으로 하며, 기존 VS Code 확장 프로그램과 완벽하게 호환됩니다. 개발자가 기존에 익숙한 환경에서 AI의 에이전틱 기능을 바로 활용할 수 있습니다.

Kiro의 핵심 컨셉
  • 프로토타입에서 프로덕션까지(Prototype to Production): 단순한 MVP 생성을 넘어 실제 운영 가능한 서비스 수준의 코드 생성을 목표로 함
  • Spec-Driven Development: 코드 생성 전에 요구사항(Requirements)→설계(Design)→작업 목록(Tasks)을 체계적으로 문서화하는 개발 방식
  • 에이전틱(Agentic): AI가 자율적으로 여러 단계의 작업을 계획하고 실행하는 능력
사용 사례: 기존 IDE 사용자의 전환

VS Code 사용자는 Kiro를 설치하는 즉시 기존 확장 프로그램(ESLint, Prettier, GitLens 등)을 그대로 사용하면서 AI 에이전트 기능을 추가로 활용할 수 있습니다. 기존 워크플로우를 바꾸지 않아도 됩니다.

코딩 에이전트의 종류
✍️Inline Copilot
코드 라인 자동완성 도구
GitHub Copilot, Amazon Q Developer 등. 개발자가 코드를 입력할 때 다음 줄을 제안. 개발자가 모든 결정권을 보유. 가장 수동적인 AI 지원 형태.
💬Chat Assistant
대화형 코드 생성 도구
ChatGPT, Claude, Gemini 등. 채팅으로 요청하면 코드 블록을 생성. 개발자가 직접 코드를 IDE에 복사·붙여넣기 해야 함. 컨텍스트 유지가 어려움.
🤖Agentic IDE ← Kiro
이번 과정에서 다루는 도구
Kiro, Cursor, Windsurf 등. AI가 파일을 직접 생성·수정하고, 여러 단계의 작업을 자율적으로 실행. 요구사항부터 코드까지 전체 흐름을 관리. 이번 과정의 핵심 도구.
3가지 코딩 에이전트 분류

AI 코딩 도구는 자율성(Autonomy) 수준에 따라 세 가지로 분류됩니다. 자율성이 높을수록 AI가 더 많은 결정을 내리고, 개발자는 고수준의 방향 설정에 집중할 수 있습니다.

각 유형 비교
  • 인라인 코파일럿(Inline Copilot): 자율성 낮음. 코드 라인 단위 제안. 대표 도구: GitHub Copilot, Amazon Q Developer. 개발자가 모든 결정을 직접 내림
  • 채팅 어시스턴트(Chat Assistant): 자율성 중간. 블록 단위 코드 생성. 채팅 인터페이스. 대표 도구: ChatGPT Code Interpreter. IDE와 분리된 경험
  • 에이전틱 IDE(Agentic IDE): 자율성 높음. 파일 생성·수정·실행을 자율적으로 수행. 대표 도구: Kiro, Cursor, Windsurf. 전체 개발 워크플로우 통합
이번 과정의 초점

이번 Agentic AI Workshop은 세 번째 유형인 에이전틱 IDE에 집중합니다. 특히 Kiro를 사용하여 실제 프로젝트를 처음부터 끝까지 구축하는 경험을 쌓습니다. Day 1–3에서는 Kiro의 기본 기능을, Day 4에서는 고급 기능(Steering, MCP, Hook, Power)을 깊이 다룹니다.

Kiro 6가지 주요 특징

Kiro의 주요 특징 중 Spec-Driven Development와 두 가지 자율성 모드는 다른 에이전틱 IDE와의 핵심 차별점입니다. 이 두 가지 기능이 함께 작동할 때 프로토타입에서 프로덕션까지의 갭을 메울 수 있습니다.

핵심 차별점 심화
  • Code OSS 기반: 오픈소스 버전의 VS Code를 기반으로 하여 기존 VS Code 사용자가 바로 사용 가능. Microsoft의 독점 확장 프로그램 일부는 호환 안 될 수 있음
  • 무료 플랜(Free Plan): GitHub·Google·AWS Builder ID로 로그인 시 무료. AWS 계정이나 신용카드 없이 시작 가능. 월 50 agent sessions 제공
  • Autopilot vs Supervised 모드: Autopilot은 AI가 자율 결정, Supervised는 각 단계에서 개발자 승인. 작업 성격에 따라 전환하여 사용
  • Spec-Driven Development: .kiro/specs/ 폴더에 requirements.md, design.md, tasks.md를 저장하여 프로젝트 컨텍스트를 영구 유지

IDE와 CLI 비교

Kiro IDE와 Kiro CLI는 동일한 AI 엔진을 사용하지만 인터페이스가 다릅니다. 이번 과정은 IDE 중심으로 진행되며, CLI는 Day 4에서 간략히 다룹니다.

각 버전의 적합한 사용 상황
  • Kiro IDE: 신규 프로젝트 개발, 코드 탐색, 실시간 편집, 팀 협업. 개발자와 비개발자 모두 사용 가능
  • Kiro CLI: GitHub Actions, Jenkins 같은 CI/CD 파이프라인에 통합. 자동화된 코드 리뷰, 테스트 생성, 문서화에 적합. 헤드리스(Headless) 서버 환경
사용 사례: CI/CD에서의 Kiro CLI

팀이 GitHub에 Pull Request를 올리면 Kiro CLI가 자동으로 코드를 분석하고, 테스트 케이스를 제안하며, 보안 취약점을 검사합니다. 개발자가 IDE를 열지 않아도 AI 코드 리뷰가 자동 실행됩니다.

Kiro IDE 주요 영역 설명

Kiro IDE는 VS Code와 거의 동일한 레이아웃을 가집니다. 차이점은 Kiro 패널(Kiro Panel)이 우측에 추가되고, .kiro/ 폴더가 프로젝트 루트에 자동 생성된다는 점입니다.

.kiro/ 폴더 구조
  • .kiro/specs/: Spec-Driven Development 파일 저장 (requirements.md, design.md, tasks.md)
  • .kiro/steering/: Steering 파일 저장 — AI에게 프로젝트 규칙과 컨벤션 지정
  • .kiro/hooks/: Hook 파일 저장 — 특정 이벤트 발생 시 자동 실행되는 스크립트
사용 사례: Diff 뷰로 변경사항 승인

Kiro가 파일을 수정할 때 Supervised 모드에서는 Diff 뷰로 변경 전/후를 나란히 보여줍니다. 개발자는 각 변경사항을 승인(Accept)/거절(Reject)할 수 있어 AI의 실수를 방지할 수 있습니다.

Kiro의 두 가지 실행 모드

Kiro는 크게 두 가지 방식으로 사용할 수 있습니다. Vibe Coding은 자연어로 빠르게 구현하는 방식이고, Spec-Based Development는 체계적인 문서화 후 구현하는 방식입니다. 두 방식은 배타적이지 않으며, 같은 프로젝트 내에서도 혼용 가능합니다.

언제 어떤 모드를 써야 하나?
  • Vibe Coding 적합: 아이디어 검증(POC), 간단한 스크립트, 개인 프로젝트, 학습 목적, 빠른 데모
  • Spec-Based 적합: 팀 프로젝트, 실제 서비스 개발, 복잡한 비즈니스 로직, 장기 유지보수가 필요한 코드
사용 사례: 모드 전환 전략

실제 프로젝트에서는 처음에 Vibe Coding으로 아이디어를 빠르게 검증한 다음, 아이디어가 확정되면 Spec-Based로 전환하여 프로덕션 수준으로 재구현하는 전략이 효과적입니다. 이 전략이 Kiro의 "프로토타입에서 프로덕션까지" 철학과 일치합니다.

설치 방법 상세

Kiro는 kiro.dev에서 운영 체제에 맞는 설치 파일을 다운로드하여 설치합니다. 기존 VS Code와 독립적으로 실행되므로, VS Code를 사용 중이더라도 별도 설치하여 함께 사용할 수 있습니다.

로그인 방법 (3가지)
  • GitHub 계정: 가장 많은 개발자가 보유. GitHub 계정이 있으면 즉시 로그인 가능
  • Google 계정: Gmail 계정으로 로그인. 개인 또는 업무용 Google 계정 모두 가능
  • AWS Builder ID: AWS 계정이 아닌 별도의 개발자 ID. AWS 콘솔 접근 권한 없음. 순수 Kiro 사용만을 위한 무료 ID. AWS 서비스 사용 불필요
주의: AWS Builder ID vs AWS 계정

AWS Builder ID는 AWS 계정(AWS Account)과 다릅니다. AWS Builder ID는 개발자 커뮤니티와 특정 AWS 도구(Kiro, AWS CodeCatalyst 등)를 위한 무료 ID입니다. AWS 계정이 없어도, 신용카드를 등록하지 않아도 Kiro를 무료로 사용할 수 있습니다.

Vibe Coding 개념

Vibe Coding은 자연어로 원하는 결과물을 설명하면 AI가 즉시 구현하는 방식입니다. 마치 직관(Vibe)만으로 코딩하는 것처럼, 기술적 세부사항을 몰라도 AI에게 결과물을 요청할 수 있습니다. 2025년 Andrej Karpathy(前 OpenAI)가 명명한 용어입니다.

Spec-Driven Development 개념

Spec-Driven Development는 코드 작성 전에 체계적인 명세서(Spec)를 먼저 작성하는 개발 방식입니다. 요구사항(Requirements) → 설계(Design) → 작업 목록(Tasks) → 구현(Implementation) 순서로 진행합니다.

언제 무엇을 쓸까?
  • Vibe Coding 적합: 빠른 프로토타이핑, 아이디어 검증, 간단한 스크립트, 개인 프로젝트
  • Spec-Based 적합: 팀 프로젝트, 복잡한 비즈니스 로직, 장기 유지보수, 프로덕션 배포

Spec-Driven Development 3단계

Spec-Driven Development(명세 기반 개발)는 코드를 작성하기 전에 명세서(Specification)를 먼저 작성하는 개발 방식입니다. 소프트웨어 공학의 기본 원칙("먼저 생각하고 나중에 코딩")을 AI 시대에 재해석한 것입니다.

각 단계 파일 구조
  • requirements.md: 사용자 스토리(User Story)와 수용 기준(Acceptance Criteria). EARS 표기법 사용. "주어진 [조건], [트리거] 시 [결과]" 형식
  • design.md: 시스템 아키텍처, 컴포넌트 다이어그램, 데이터 모델, API 설계, 기술 스택 정의
  • tasks.md: 체크박스 형식의 구체적 작업 목록. 각 Task는 독립적으로 검증 가능한 단위. AI가 순차적으로 실행
사용 사례: 이커머스 사이트 Spec 작성

전자상거래 사이트 개발 시 Requirements에서 "사용자는 상품을 장바구니에 담을 수 있어야 한다"를 정의하면, Design에서 장바구니 컴포넌트와 데이터 구조를 설계하고, Tasks에서 "장바구니 데이터 모델 구현", "장바구니 API 엔드포인트 생성", "장바구니 UI 컴포넌트 구현" 등으로 세분화됩니다. AI는 이 Tasks를 순서대로 실행하며 구현합니다.

Spec-Driven Development — 2 (Tasks 실행)
🎯구체적·검증 가능 단위
Task = 하나의 명확한 목표
각 Task는 "무엇을 해야 하는가"가 명확합니다. 완료 여부를 객관적으로 검증 가능. 예: "User 모델에 email 필드 추가 + 마이그레이션 생성 + 유효성 검사 구현"
✅체크박스 진행 추적
완료된 작업을 시각적으로 관리
tasks.md에 - [ ] 형식으로 작성. AI가 Task 완료 시 자동으로 - [x]로 변경. 전체 프로젝트 진행률을 한눈에 파악 가능.
🔄AI 순차 실행
Tasks를 AI가 자동으로 순서대로 처리
AI가 Tasks를 위에서 아래로 순차 실행. 각 Task의 의존성을 파악하여 올바른 순서로 실행. Supervised 모드에서는 각 단계마다 승인 요청.
# tasks.md 예시
- [x] 1. 프로젝트 구조 초기화 및 의존성 설치
- [x] 2. 데이터베이스 스키마 및 모델 생성
- [ ] 3. 장바구니 API 엔드포인트 구현 ← 현재
- [ ] 4. 프론트엔드 컴포넌트 구현
- [ ] 5. 결제 통합 및 에러 처리
Tasks 실행의 핵심 원칙

Tasks는 대규모 프로젝트에서 AI가 일관성을 유지하며 구현을 진행할 수 있게 하는 핵심 메커니즘입니다. 각 Task는 독립적으로 실행될 수 있을 만큼 충분히 작지만, 의미 있는 결과물을 생성할 만큼 충분히 큽니다.

좋은 Task의 특성
  • 구체성(Specificity): "기능 구현" 대신 "User 모델에 email 필드 추가 + 유효성 검사 + 테스트 작성"처럼 구체적으로
  • 검증 가능성(Verifiability): 완료 여부를 명확히 판단할 수 있어야 함
  • 독립성(Independence): 가능한 한 다른 Tasks에 의존하지 않도록 설계
  • 적절한 크기(Right Size): 너무 크거나(모호함) 너무 작으면(오버헤드) 비효율적
사용 사례: 대규모 프로젝트에서의 일관성

20개 파일에 걸친 복잡한 기능을 구현할 때, Tasks 없이 단순 Vibe Coding을 사용하면 AI가 앞서 만든 파일의 구조를 기억하지 못해 불일치가 발생합니다. Tasks 파일이 있으면 AI는 항상 같은 설계 문서를 참조하여 일관된 코드를 생성합니다.

Vibe vs Spec 선택 기준

두 방식의 선택은 복잡도(Complexity)와 프로덕션 요건(Production Requirements)을 기준으로 합니다. 단순하고 탐색적인 작업에는 Vibe가 빠르고, 복잡하고 프로덕션 수준의 품질이 필요한 경우 Spec이 필요합니다.

4분면 분석
  • 낮은 복잡도 + 탐색적: Vibe Coding — 개인 스크립트, 간단한 CLI 도구, 빠른 데모
  • 높은 복잡도 + 탐색적: 혼합 방식 — 핵심 기능은 Spec, 부수 기능은 Vibe
  • 낮은 복잡도 + 프로덕션: Vibe Coding — 단순한 마이크로서비스, 간단한 Lambda 함수
  • 높은 복잡도 + 프로덕션: Spec-Driven Development — 이커머스 플랫폼, SaaS 앱, 기업용 시스템
사용 사례: Workshop 1의 전략

Kiro CLI 소개

Kiro CLI(Command Line Interface)는 터미널에서 Kiro의 모든 기능을 사용할 수 있는 도구입니다. GUI 없이도 동일한 AI 모델과 기능을 활용할 수 있으며, CI/CD(Continuous Integration/Continuous Deployment) 파이프라인에 통합하기에 최적화되어 있습니다.

주요 CLI 명령어
  • kiro init [프로젝트명]: 새 Kiro 프로젝트를 초기화하고 .kiro/ 폴더 구조를 생성
  • kiro vibe "[지시]": 자연어 명령으로 Vibe Coding 실행. 파일을 직접 생성·수정
  • kiro spec create --name [이름]: 새 Spec을 생성하고 requirements.md, design.md, tasks.md 초안 자동 생성
  • kiro spec run --auto: Tasks를 자동으로 순차 실행. CI/CD에서 사용
  • kiro review: 현재 코드 변경사항을 AI가 리뷰하고 개선 사항 제안
사용 사례: GitHub Actions에서 Kiro CLI

개발자가 Pull Request를 올리면 GitHub Actions가 자동으로 kiro review를 실행하여 코드 품질, 보안 취약점, 테스트 커버리지를 분석합니다. AI 코드 리뷰가 자동화되어 팀의 코드 품질이 일관되게 유지됩니다.

IDE와 CLI 선택 기준

Kiro IDE와 Kiro CLI는 동일한 AI 모델을 사용하므로 생성 코드의 품질은 같습니다. 차이는 인터페이스(Interface)와 자동화 가능성에 있습니다. 많은 팀이 개발 시에는 IDE를, 배포 파이프라인에서는 CLI를 사용하는 혼합 전략을 채택합니다.

각각 언제 사용하는가
  • IDE를 사용할 때: 신규 기능 개발, 코드 탐색, 디버깅, 대화형 코드 작성, 학습 목적
  • CLI를 사용할 때: Pull Request 자동 리뷰, 코드 생성 자동화, 문서 자동 업데이트, 헤드리스 서버에서 코드 작업, 배치 처리
사용 사례: 팀의 혼합 전략

한 스타트업 팀은 개발자들이 Kiro IDE로 개발하고, CI/CD 파이프라인에서 Kiro CLI가 자동으로 테스트 케이스를 생성하고 코드를 리뷰합니다. 개인 개발 생산성과 팀 코드 품질을 동시에 향상시키는 전략입니다.

Kiro의 5가지 핵심 장치 개요

Kiro는 5가지 핵심 장치로 AI의 행동을 세밀하게 제어할 수 있습니다. Day 1에서는 기본 사용법(Vibe Coding, Spec)을 배우고, Day 4에서 모든 장치를 심화 학습합니다.

5가지 장치 개요
  • Steering(조향): AI에게 프로젝트의 일관된 규칙과 컨벤션을 알려주는 파일. 한 번 설정하면 모든 대화에 자동 적용
  • Spec(명세): 오늘 배운 Spec-Driven Development의 핵심 파일들
  • MCP(Model Context Protocol): GitHub, Jira, 데이터베이스 등 외부 시스템과 AI를 직접 연결하는 프로토콜
  • Hook(훅): 파일 저장, 코드 변경 등 특정 이벤트 발생 시 자동으로 실행되는 자동화 스크립트
  • Power(파워): Kiro의 기능을 확장하는 플러그인과 도구 생태계
사용 사례: 다섯 가지가 함께 작동할 때

Steering이 "항상 TypeScript를 사용하고 함수형 스타일로 코딩"을 정의하고, Spec이 기능을 명세하며, MCP가 GitHub에서 관련 이슈를 가져오고, Hook이 파일 저장 시 자동으로 테스트를 실행하며, Power가 TypeScript 최적화 도구를 제공합니다. 이 다섯 가지가 함께 작동할 때 Kiro의 진정한 힘이 발휘됩니다.

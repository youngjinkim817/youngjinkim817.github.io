단계 1: 사용 사례 정의 (주 1-2)
예시: 고객지원 FAQ 챗봇 도입
  • 목표: FAQ 응답 자동화 → 상담사 업무 50% 절감
  • 사용자: 전사 고객지원팀 (50명)
  • 성공 기준: 정확도 90% 이상, 응답 시간 3초 이내
  • 생성형 AI 적합성 검토: 반복 Q&A 패턴 → 적합
단계 2: AWS 서비스 선택 (주 2-3)
선택: Amazon Bedrock + Knowledge Bases
  • 서비스: Amazon Bedrock (Knowledge Base 연동 RAG 구현)
  • 모델: Amazon Nova Micro (단순 FAQ, 저비용)
  • 이유: 단일 지식 기반 Q&A → AgentCore 불필요 (과도한 엔지니어링 방지)
  • 예상 비용: 월 5만 요청 × 500 토큰 ≈ $4/월
단계 3: 책임 있는 AI 계획 (주 3-4)
도구: Amazon Bedrock Guardrails
  • 콘텐츠 필터: 욕설·유해 콘텐츠 차단 설정
  • 금지 주제: "법률 조언", "의료 진단" 등 범위 이탈 요청 거부
  • 공정성: 모든 사용자에게 동일한 응답 품질 보장
  • 원칙: 계획 단계에서 구성 → 나중에 추가하면 재작업 비용 발생
단계 4: POC 구현 (주 4-6)
도구: Amazon Bedrock 콘솔
  • 2주 스프린트: 제품 매뉴얼 PDF → S3 → Knowledge Base 생성
  • 테스트: 20개 샘플 질문으로 정확도 측정 → 89% 달성
  • 모델 비교: Nova Micro vs Nova Lite — 품질/비용 트레이드오프 확인
  • Guardrails 검증: 금지 주제 필터 동작 확인
단계 5: 프로덕션 배포 (주 6-8)
결과: 배포 완료, 상담사 업무 47% 절감
  • Guardrails 버전 고정: 검증된 설정을 프로덕션에 고정
  • CloudWatch 모니터링: 토큰 사용량·응답 시간·오류율 대시보드
  • 예산 알림: 월 $50 초과 시 알림 설정
  • 피드백 루프: 사용자 만족도 → Knowledge Base 지속 개선
섹션 1: 프로젝트 계획 기초(Project Planning Fundamentals)
  • 성공한 생성형 AI 프로젝트와 실패한 프로젝트의 가장 큰 차이: 체계적인 계획(Structured Planning)
  • 기술적 스킬 이상의 것이 필요 — 사용 사례 정의, 서비스 선택, 거버넌스, 비용 관리
  • 4가지 구성 요소는 순차 체크리스트가 아닌 상호 연결된 고려 사항(Interconnected Considerations)
스타트업 FAQ 챗봇 도입 사례 — 8주 여정
  • 1-2주: 사용 사례 정의 (FAQ 응답 자동화, 상담사 업무 50% 절감 목표)
  • 2-3주: Amazon Bedrock + Knowledge Bases 선택, 비용 추정 (Nova Micro, 월 $4)
  • 3-4주: Guardrails 구성 (욕설 차단, 범위 이탈 요청 거부)
  • 4-6주: POC 구현, 정확도 89% 달성
  • 6-8주: 프로덕션 배포, CloudWatch 모니터링, 상담사 업무 47% 절감

책임 있는 AI 통합 — 계획 단계에서 시작
  • 사후 고려가 아닌 설계 내장(Design-Embedded) 원칙으로 접근
  • HR 어시스턴트 적용 책임 있는 AI 차원: 공정성(Fairness), 안전성(Safety), 거버넌스(Governance), 진실성/견고성(Veracity & Robustness)
  • Amazon Bedrock Guardrails: 콘텐츠 필터, 금지 주제, 컨텍스트 근거 검사 — 계획 단계에서 구성
비용 관리(Cost Management) 핵심 원칙
  • 적합한 규모의 모델 선택(Right-Sizing): 품질 요건을 충족하는 가장 비용 효율적 모델
  • 토큰 사용량 추정(Token Estimation): 요청 수 × 평균 입력/출력 토큰 수 예측
  • 소규모 시작(Start Small): POC → 비용 검증 → 스케일링
모델 비용 비교 (월 10만 요청, 평균 500 토큰 기준)
  • Amazon Nova Micro: ~$4/월 — 단순 FAQ, 고빈도 처리에 최적
  • Amazon Nova Lite: ~$6/월 — 균형형, 중간 복잡도 RAG
  • Amazon Nova Pro: ~$80/월 — 복잡한 추론, 멀티모달
  • Claude Haiku 3.5: ~$25/월 — 빠른 고품질 응답
  • Claude Sonnet 3.7: ~$300/월 — 최고 품질, 코딩/복잡 분석
  • 원칙: 품질 요건이 허용하면 Nova Micro/Lite 선택 → 동일 품질, 낮은 비용

A서비스 복잡성이 실제 비즈니스 요구 사항과 일치하도록 하여 과도한 엔지니어링을 방지합니다.  ✔ 정답

D팀이 너무 비싼 파운데이션 모델을 선택하는 것을 방지합니다.
해설: 정답 A: 문제를 먼저 정의하면 실제 비즈니스 요구 사항에 맞는 서비스를 선택할 수 있습니다. 서비스 복잡성을 문제 복잡성에 맞추는 것이 핵심 원칙입니다.

  • 정답 A: 서비스 복잡성이 실제 비즈니스 요구 사항과 일치하도록 하여 과도한 엔지니어링을 방지

  • 역순(서비스 먼저 선택) → 기술이 이끄는 설계 → 과도한 복잡성 발생

지식 확인 2 — 정답

팀에서 단일한 지식 기반을 사용하여 회사 정책에 대한 질문에 답변하는 간단한 FAQ 챗봇을 구축하고 있습니다. 이 팀에서 구현을 위해 Amazon Bedrock AgentCore를 사용하는 것을 고려하고 있습니다. 모듈의 서비스 선택 원칙에 따르면 이러한 접근 방식은 어떻습니까?
AKnowledge Base를 사용할 때마다 AgentCore가 필요합니다.
BAgentCore는 가장 견고한 플랫폼을 제공하기 때문에 올바른 선택입니다.
CAgentCore는 Knowledge Bases 통합을 지원하므로 적합합니다.
DAgentCore는 이 사용 사례에 대해 과도하게 엔지니어링할 가능성이 높습니다. Knowledge Base를 갖춘 간단한 Amazon Bedrock 구현이 문제의 복잡성에 더 잘 맞을 것입니다.  ✔ 정답
해설: 정답 D: 간단한 FAQ 챗봇에는 단일 파운데이션 모델을 갖춘 Amazon Bedrock만 필요합니다. AgentCore는 다단계 에이전트 워크플로를 위한 것이며, 단순 RAG 챗봇에 적용하면 불필요한 복잡성만 추가됩니다.
KC2 정답 해설 — D) AgentCore 과도한 엔지니어링
  • 정답 D: AgentCore는 이 사용 사례에 과도하게 엔지니어링될 가능성이 높음
  • 단순 FAQ 챗봇에 필요한 것: Amazon Bedrock + Knowledge Base (RAG)
  • AgentCore가 필요한 경우: 도구 사용, 외부 API 호출, 다단계 의사결정이 필요한 워크플로
과정 전체 핵심 메시지
  • 책임 있는 AI는 사후 추가가 아닌 설계 단계에서 내장
  • 서비스 선택은 기능이 아닌 문제 복잡성 기준
  • 가드레일 + 프롬프트 엔지니어링 + 시스템 프롬프트 = 심층 방어(Defense in Depth)
  • 모든 생성형 AI 프로젝트의 성공은 체계적인 계획에서 시작

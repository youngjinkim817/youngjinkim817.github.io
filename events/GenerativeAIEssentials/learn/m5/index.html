모듈 5: Amazon Bedrock Guardrails

모듈 소개

Amazon Bedrock Guardrails는 책임 있는 AI 원칙을 기술적으로 구현하는 완전관리형 보호 계층입니다.

  • 콘텐츠 필터, 주제 거부, PII 편집 등 6가지 정책 유형을 제공합니다.
  • 모든 파운데이션 모델과 에이전트에 일관되게 적용됩니다.
  • 입력과 출력 양방향을 보호하여 책임 있는 AI를 실현합니다.

이 모듈에서 학습할 내용은 다음과 같습니다.

1

Amazon Bedrock Guardrails의 용도 및 기능을 설명한다.

가드레일 안전 장치 유형을 책임 있는 AI 차원에 매핑한다.

5

5가지 학습 목표

  • 자동 추론 검사(Automated Reasoning): 99% 정확도로 사실 오류 최소화
  • 가드레일 적용 범위 평가: 충분한 경우 vs 추가 거버넌스 필요한 경우 판단

섹션 1: Amazon Bedrock Guardrails 개요 및 구성
  • Guardrails의 두 가지 핵심 동작: 차단(Block) — 요청 거부 / 익명화(Anonymize) — 민감 정보 마스킹

Guardrails 아키텍처 특성
  • 입력·출력 동시 평가: 사용자 입력 검사 후 FM 전달 → FM 응답 검사 후 사용자 전달
  • 모델 독립성(Model Agnostic): Nova, Claude, Llama 등 모든 Bedrock 모델에 동일 적용
  • 정책 기반 구성: 6가지 정책 유형 중 필요한 것만 선택 활성화 — 과도한 차단 방지
  • 자동 개입(Automatic Intervention): 정책 위반 감지 시 즉시 차단 또는 마스킹
책임 있는 AI 원칙과 Guardrails의 연결
  • 안전성(Safety) → 콘텐츠 필터로 유해 콘텐츠 차단
  • 제어 가능성(Controllability) → 프롬프트 공격 탐지로 시스템 무결성 보호
  • 개인정보보호/보안(Privacy & Security) → PII 편집으로 개인정보 보호
  • 진실성/견고성(Veracity & Robustness) → 컨텍스트 근거 검사로 환각 최소화

Amazon Bedrock 가드레일이란?

Amazon Bedrock 가드레일(Guardrails) 개요
  • 사용자 프롬프트 및 모델 응답에서 바람직하지 않은 콘텐츠 보호
  • 에이전트, 지식 베이스 및 내·외부 호스팅 모델과 함께 작동
7가지 핵심 보호 기능
  • 콘텐츠 필터링(Content Filtering): 유해한 텍스트 및 이미지 콘텐츠 감지·필터링
  • 프롬프트 공격 보호(Prompt Attack Protection): 탈옥(Jailbreak), 프롬프트 주입(Prompt Injection), 프롬프트 유출(Prompt Leakage) 방어
  • 주제 차단(Topic Blocking): 짧은 자연어 설명으로 특정 주제 토픽 정의·차단
  • PII 편집(PII Redaction): 생성형 AI 애플리케이션에서 개인 식별 정보(PII) 및 민감 정보 편집
  • 자동화된 추론 검사(Automated Reasoning Check): 최대 99% 정확도로 올바른 모델 응답 식별, AI 환각(Hallucination)·데이터 모호성·사실 오류 최소화
  • 환각 필터링(Grounding Filter): 컨텍스트 기반으로 모델 응답의 근거성(Groundedness)·관련성(Relevance) 감지
  • 단어 필터(Word Filter): 사용자 입력 및 모델 응답에서 감지·차단할 단어 집합 정의
사용 사례: AWS 고객지원 봇에 Guardrails 적용
  • 콘텐츠 필터: 욕설·폭력적 표현이 담긴 사용자 입력 차단
  • 주제 차단: "경쟁사 클라우드 서비스 추천" 요청 자동 거부
  • PII 편집: 고객이 입력한 신용카드 번호, 이메일 주소 마스킹
  • 환각 필터링: 지식 기반에 없는 AWS 서비스 사양 오답 차단

예시
🏦 금융 서비스 챗봇

추론: 규정 준수 (금융 서비스 법률)
샘플 문구: "삼성전자 지금 사야 해?" / "어떤 ETF가 좋아?"
모범 사례
  • 주제당 최대 5개의 샘플 문구 추가 → 탐지 정확도 향상
  • 추론(Rationale) 작성 → 팀 공유 및 감사 추적용
  • 유사 주제는 그룹화하여 가드레일 수 최소화
콘텐츠 필터(Content Filters) — 6가지 범주
  • 혐오(Hate): 보호 특성(인종, 성별, 종교 등) 기반 혐오 표현
  • 모욕(Insults): 개인·집단 비하 언어
  • 성적 콘텐츠(Sexual): 성인용 노골적 콘텐츠
  • 폭력(Violence): 폭력 묘사, 자해, 위협
  • 위법 행위(Misconduct): 불법 활동 조장
  • 프롬프트 공격(Prompt Attacks): 탈옥, 인젝션 시도 — 입력에만 적용
금지 주제(Denied Topics) — 의미 기반 차단
  • 단어 목록이 아닌 자연어 설명(Natural Language Definition)으로 주제 정의
  • 동의어·우회 표현까지 ML이 의미 기반으로 탐지
  • 예시: "구체적인 주식 매매 추천, 포트폴리오 구성 조언 등 투자 자문에 해당하는 모든 요청"
콘텐츠 필터 강도 설정 가이드
  • 없음(None): 필터 비활성화 — 내부 도구·실험 환경
  • 낮음(Low): 명백한 위반만 차단
  • 중간(Medium): 일반 B2C 서비스 권장
  • 높음(High): 어린이 서비스, 금융·의료 규제 환경

자동 추론(Automated Reasoning)
형식 논리로 정책 문서 기반 응답을 수학적 검증합니다.
주요 기능
  • 최대 99% 정확도
  • 입증 가능한 증거 제공
  • 결정론적 정확성
사용 예시
금융·의료·법률 규제 준수 시나리오에서
응답이 정책 문서를 준수하는지 자동 검증
요금 안내: 각 정책 유형은 독립적으로 책정 — 활성화한 정책에 대해서만 비용 발생 | 핵심 인사이트: 패턴 일치(단어 필터) → 개인정보·환각 탐지 → 수학적 정책 준수로 발전하는 4가지 보호 계층
단어 필터(Word Filter)
  • 최대 10,000개 단어/문구 등록 — 대소문자 무관
  • 욕설 관리형 목록(Managed Profanity List): AWS 제공 기본 욕설 목록 활성화 가능
  • 단순 패턴 매칭 — 우회 표현 취약 → 금지 주제와 병행 권장
PII 편집(PII Redaction) 동작 비교
  • BLOCK: PII 포함 요청 전체 거부 — 민감 업무(금융 거래 등)
  • ANONYMIZE: PII를 [NAME], [EMAIL] 등 자리 표시자로 대체 — 처리 흐름 유지
  • 지원 유형: 이름, 이메일, 전화번호, SSN, 신용카드, 주소, 운전면허 등
컨텍스트 근거(Grounding Check) vs 자동 추론(Automated Reasoning)
  • Grounding Check: 참조 소스(RAG) 기반 환각 탐지 — 임계값 설정 / RAG 연동 필수
  • Automated Reasoning: 수학적 증명 기반 사실 검증 — 99% 정확도 / 사용자 정의 정책 적용
PII 편집 실전 예시
  • 입력: "제 이름은 홍길동이고 이메일은 hong@example.com입니다"
  • ANONYMIZE 적용 후: "제 이름은 [NAME]이고 이메일은 [EMAIL]입니다"
  • 처리 흐름은 유지되면서 개인정보는 보호됨

  • 콘텐츠 필터는 혐오·폭력·성적 콘텐츠 등 유해성 기반 — 투자 조언 차단에는 부적합

모듈 7 개요
  • M1~M6에서 구축한 기술적 구현을 AI를 책임 있게 대규모로 배포하는 데 필요한 조직적 구조와 연결
  • 거버넌스(Governance): 정책, 프로세스, 역할, 책임 구조의 조합 — 기술 제어를 관리하는 상위 프레임워크
  • 보안, 거버넌스, 규정 준수는 사후 고려 사항이 아닌 AI 개발·배포의 모든 단계에 반영해야 하는 기본 요소
M1~M7 연계
  • M1: 책임 있는 AI 8차원 → M7에서 거버넌스(Governance) 차원을 조직 수준으로 심화
  • M5: Amazon Bedrock Guardrails → M7: 기술 제어를 언제·어떻게 구성·적용할지 결정하는 조직 정책
  • M6: 에이전틱 AI 실행 가드레일 → M7: 다단계 에이전트를 포함하는 규정 준수 의무

모듈 7 학습 목표

이 모듈에서 학습할 내용은 다음과 같습니다.

1

AI 거버넌스 프레임워크의 주요 구성 요소(정책, 소유권, 감사 추적)를 설명한다.

2

AI 배포와 관련된 규제 프레임워크(HIPAA, PCI DSS, GDPR 등)를 식별한다.

3

AI 거버넌스에서 법률 및 규정 준수 전문 지식이 필요한 이유를 인식한다.

3가지 학습 목표
  • AI 거버넌스 프레임워크(AI Governance Framework): 주요 구성 요소(정책, 소유권, 감사 추적) 설명
  • 규제 프레임워크(Regulatory Framework): AI 배포와 관련된 HIPAA, PCI DSS, GDPR 등 식별
  • 법률 및 규정 준수 전문 지식(Legal & Compliance Expertise): AI 거버넌스에서 법적 전문 지식이 필요한 이유 인식
모듈 전체 흐름
  • 섹션 1: 거버넌스 프레임워크 — 정의 → 왜 필요한가 → 구성 요소
  • 섹션 2: 규정 준수 요구 사항 — 공동 책임 모델 → 6가지 규정 준수 프로그램 → AWS Artifact
  • 지식 확인: 거버넌스 한계 시나리오 + AWS Artifact 정의

  • M1: 책임 있는 AI 8차원 중 개인정보보호/보안(Privacy & Security), 거버넌스(Governance) 소개
  • M2: Amazon Bedrock의 플랫폼 보안 — 콘텐츠 필터링, 암호화, 액세스 제어
  • M4: 프롬프트 공격 벡터(탈옥·인젝션·추출) + 심층 방어(Defense in Depth) 아키텍처
  • M5: Amazon Bedrock Guardrails — 6가지 정책 유형으로 입력·출력 양방향 보호
  • M6: 에이전틱 AI 실행 가드레일 + CloudTrail 감사 로깅
  • M7: 보안 제어를 관리하고 책임 구조를 정의하는 거버넌스 + 규제 의무 규정 준수
보안 단독으로 충분하지 않은 이유
  • 보안만: 기술 제어 존재 — 하지만 누가 제어하고 책임지는지 불명확
  • 거버넌스 추가: 제어의 소유자, 적용 시기, 예외 처리 방식을 정의
  • 규정 준수 추가: 외부 규제 기관이 요구하는 증명 가능한 기록 제공

거버넌스(Governance) 정의

조직이 AI 시스템을 책임감 있게 개발·운영하기 위해 수립하는 정책, 프로세스, 역할, 책임 구조의 조합

단순히 보안에 국한되지 않음 — 보안, 규정 준수, 비용 관리, 운영 표준, 윤리적 감독이 함께 작동

거버넌스(Governance) 정의
  • AI 맥락에서의 거버넌스: 조직이 AI 시스템을 책임감 있게 개발·운영하기 위해 수립하는 정책, 프로세스, 역할, 책임 구조의 조합
  • 단순히 보안에 국한되지 않음 — 보안(Security), 규정 준수(Compliance), 비용 관리(Cost Management), 운영 표준(Operational Standards), 윤리적 감독(Ethical Oversight)이 함께 작동
거버넌스 프레임워크의 5가지 구성 요소
  • 조직 정책(Organizational Policies): AI 사용 허용 범위, 금지 사항, 에스컬레이션 경로 정의
  • 승인 워크플로(Approval Workflows): 새 AI 모델·기능 배포 전 검토 및 승인 절차
  • 명확한 소유권(Clear Ownership): AI 시스템별 책임자 지정 — 문제 발생 시 대응 주체 명확화
  • 감사 추적(Audit Trails): 누가 무엇을 언제 결정했는지 기록 — CloudTrail, 로깅 포함
  • 정기적 검토(Regular Reviews): 배포 후 지속적인 성과 평가 및 정책 업데이트
기술적 제어 vs 거버넌스 프레임워크
  • M5 Guardrails = 기술적 제어: 콘텐츠 필터를 어떻게 적용하는가
  • M7 거버넌스 = 조직 구조: 콘텐츠 필터를 언제·왜·누가 결정하는가
  • 두 계층 모두 필요 — 기술 제어는 거버넌스 프레임워크 내에서 운영될 때 효과적

생성형 AI에 거버넌스가 중요한 이유

인터랙티브
비결정론적 출력(Non-Deterministic Output) +
동일한 입력에서 매번 다른 응답 — 온도(Temperature)·샘플링 파라미터로 인한 가변성 → 허용 범위 유지를 위한 모니터링·제어 메커니즘 필요
신속한 기능 변화(Rapid Capability Evolution) +
Amazon Bedrock을 통해 새 파운데이션 모델이 빠르게 출시 → 프로덕션 배포 전 평가·승인 프로세스 포함 필요
광범위한 조직 영향(Cross-Departmental Impact) +
마케팅, 고객 서비스, 코드 개발 등 다양한 부서 → 중앙 집중식 거버넌스 없으면 팀별 일관성 없는 AI 채택 → 위험 노출 및 규정 준수 격차
적대적 프롬프트 위험(Adversarial Prompt Risk) +
탈옥(Jailbreak), 인젝션(Injection), 추출(Extraction) 시도 — 기술 제어 + 조직 정책 병행 필요
책임 요구 사항(Accountability Requirements) +
유해하거나 잘못된 출력 발생 시 명확한 소유권 구조 필요 — 검토·수정·커뮤니케이션 담당자 사전 정의
생성형 AI 고유의 5가지 거버넌스 문제
  • 비결정론적 출력(Non-Deterministic Output): 동일한 입력에서 매번 다른 응답 — 온도(Temperature)·샘플링 파라미터로 인한 가변성 → 허용 범위 유지를 위한 모니터링·제어 메커니즘 필요
  • 신속한 기능 변화(Rapid Capability Evolution): 새 파운데이션 모델(Foundation Model)이 빠르게 출시 → 프로덕션 배포 전 평가·승인 프로세스 필요
  • 광범위한 조직 영향(Cross-Departmental Impact): 마케팅, 고객 서비스, 코드 개발 등 다양한 부서 → 중앙 집중식 거버넌스 없으면 위험 노출 및 규정 준수 격차
  • 적대적 프롬프트 위험(Adversarial Prompt Risk): 탈옥(Jailbreak), 인젝션(Injection), 추출(Extraction) 시도 — 기술 제어 + 조직 정책 병행 필요
  • 책임 요구 사항(Accountability Requirements): 유해하거나 잘못된 출력 발생 시 명확한 소유권 구조 필요 — 검토·수정·커뮤니케이션 담당자 사전 정의
기존 IT 거버넌스의 한계
  • 기존 IT 거버넌스: 결정론적(Deterministic) 소프트웨어 가정 — 동일 입력 → 동일 출력
  • 생성형 AI: 비결정론적 → 기존 테스트·검증 방법 적용 불가
  • 기존 거버넌스에만 의존 시 5가지 고유 문제 미해결 → AI 전용 거버넌스 프레임워크 필요

  • EU 사용자 대상 서비스: AI 생성 데이터 포함 개인 데이터 처리 → GDPR(General Data Protection Regulation) 적용

중요 구분

AWS 규정 준수 인증은 인프라를 다룹니다. PCI DSS를 준수하는 AWS 인프라에서 생성형 AI 애플리케이션을 실행해도, 애플리케이션 자체가 자동으로 PCI DSS를 준수하는 것은 아닙니다. 워크로드(애플리케이션, 데이터 처리, 접근 제어)에 대한 별도 검증이 필요합니다.

AWS 책임 — 클라우드 자체의 보안(Security OF the Cloud)
  • 물리적 데이터 센터 보안 및 유지 관리
  • 네트워킹 하드웨어, 하이퍼바이저(Hypervisor), 호스트 운영 체제
  • 인프라 계층 규정 준수 인증 유지: SOC, ISO, PCI DSS (인프라 범위)
고객 책임 — 클라우드 내부의 보안(Security IN the Cloud)
  • 게스트 운영 체제 패치 적용 및 애플리케이션 구성
  • 데이터 암호화 선택 — 전송 중(in-transit) 및 저장 중(at-rest)
  • IAM(Identity and Access Management): 자격 증명 및 액세스 관리
  • Amazon Bedrock: 모델이 데이터를 처리하는 방식, 모델이 생성하는 출력, 서비스 구성 방법
  • 네트워크 및 방화벽 구성 — VPC, 보안 그룹, 네트워크 ACL
핵심 구분: PCI DSS 적용 예시

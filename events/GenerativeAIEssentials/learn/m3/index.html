모듈 3: 멀티모달 AI 및 사용 사례

모듈 소개

멀티모달 AI는 텍스트, 이미지, 음성, 비디오 등 다양한 유형의 콘텐츠를 동시에 처리하고 생성할 수 있는 AI 시스템입니다.

  • 멀티모달 AI는 단일 모달 대비 더 풍부한 이해·생성이 가능합니다.
  • 의료, 금융, 제조, 소매 등 다양한 산업에서 실제 적용됩니다.
  • 책임 있는 AI 평가 게이트를 통해 사용 사례를 체계적으로 검토합니다.

모듈 개요

4가지 콘텐츠 모달리티

최신 생성형 AI(Generative AI) 시스템은 AI가 처리 또는 생성할 수 있는 고유한 유형의 데이터인 4가지 기본 콘텐츠 모달리티(Content Modality)를 사용합니다.

  • 텍스트(Text): 가장 확립된 모달리티. 문서 요약, Q&A, 코드 작성. Amazon Nova Micro/Lite.
  • 이미지(Image): 사진 분석·객체 감지·텍스트 추출(이해) + 텍스트 설명에서 새 이미지 생성. Amazon Nova Canvas.
  • 비디오(Video): 시간 경과에 따른 시각적 프레임 분석 및 비디오 생성. Amazon Nova Reel.
  • 오디오(Audio): STT(Speech-to-Text), TTS(Text-to-Speech), 실시간 대화. Amazon Nova Sonic.
멀티모달 통합 사례

이미지 업로드 + 텍스트 질문 → 음성 답변 반환. 세 가지 모달리티를 하나의 워크플로에서 활용.

이해 vs. 생성 — 별개의 기능

입력 모달리티(Input Modality)와 출력 모달리티(Output Modality)는 모델마다 다른 별개의 기능입니다. 텍스트·이미지를 이해할 수 있는 모델이라도 이미지를 생성할 수 없을 수 있습니다.

  • Claude 3.5 Sonnet: 텍스트·이미지·문서 입력, 텍스트만 출력. 이미지 이해 가능, 생성 불가.
  • Amazon Nova Sonic: 텍스트·음성 입력·출력. 실시간 대화형.
  • Titan Image Generator G1 v2: 텍스트·이미지 입력, 이미지만 출력. 생성 전문.
  • Nova Multimodal Embedding: 모든 모달리티 → 벡터 임베딩. RAG 최적.
설계 핵심 질문

모델 선택 시 항상 두 가지를 구분하세요: 1) 이해해야 할 것(입력) vs. 2) 생성해야 할 것(출력).

Amazon Bedrock — 통합 멀티모달 플랫폼

Amazon Bedrock은 인프라 관리 없이 다양한 AI 공급자의 모델에 액세스할 수 있는 통합 플랫폼입니다. Converse API는 멀티모달 입력 형식을 표준화하여 모델 간 전환 시 코드 재작성이 불필요합니다.

Converse API 활용

비전 지원 모델 간 전환 시 코드 재작성 불필요. 공급자 종속(Vendor Lock-in) 감소. Claude → Nova 전환 시 동일 API 사용.

멀티모달 파이프라인 비교

많은 실제 멀티모달 솔루션은 지연 시간 또는 비용 요구 사항을 충족하기 위해 멀티모달 파운데이션 모델(Multimodal Foundation Model) 외에 전용 AI 서비스 파이프라인을 함께 사용합니다.

  • 접근 방식 1 (멀티모달 FM): 단일 모델, 빠른 프로토타이핑. 지연 시간 증가 가능.
  • 접근 방식 2 (전용 파이프라인): Amazon Textract로 텍스트 추출 후 Bedrock에 전달. 비용 절감, 결정론적.
선택 기준

실시간 대화가 필요하면 접근 방식 1. 비용·결정성이 중요하면 접근 방식 2 (Amazon Textract + Bedrock). Amazon Textract는 문서에서 텍스트·표·양식을 정확하게 추출하는 전용 서비스.

환자 문해력 수준·언어·건강 상태에 맞게 교육 자료 자동 생성. 환자 참여도와 이해도 향상.
HIPAA 규정 준수: BAA 체결 필수 · IAM 최소 권한 · AWS KMS 암호화 · AWS CloudTrail 감사 로그 — Amazon Bedrock은 HIPAA 적격 서비스
의료 AI — 3가지 핵심 사용 사례

의료 분야에서는 임상 기록, 퇴원 요약, 영상 의학 보고서, 연구 문헌 등 방대한 비정형 데이터가 생성됩니다. Amazon Bedrock은 HIPAA 적격 서비스로 개인 정보 보호 요구 사항을 충족합니다.

  • 임상 문서 요약(Clinical Document Summarization): 긴 임상 기록을 구조화된 형식으로 요약.
  • Amazon Comprehend Medical: 의학 용어 특화 결정론적 NLP. 약물·질환·복용량 추출.
  • 환자 커뮤니케이션(Patient Communication): 문해력·언어에 맞춘 개인화 교육 자료 생성.
HIPAA 규정 준수 4단계

1) BAA(Business Associate Agreement) 체결 필수. 2) IAM 최소 권한. 3) AWS KMS 암호화. 4) AWS CloudTrail 감사 로그. Amazon Bedrock은 HIPAA 적격 서비스.

금융 서비스 — AI 아키텍처 구분

금융 서비스 조직은 매일 수백만 건의 거래를 처리합니다. 속도, 정확성, 규정 준수의 균형이 핵심입니다.

  • 실시간 사기 탐지(Real-time Fraud Detection): 100ms 이하 응답 필요. 목적별 ML(Purpose-built ML) 사용. Amazon SageMaker, AutoGluon 활용.
  • 사후 분석(Post-hoc Analysis): 사기 패턴 요약, 내러티브 보고서, 규제 문서 작성. Amazon Bedrock, Bedrock Agents 활용.
왜 실시간 탐지에 생성형 AI를 쓰지 않나?

실시간 채점은 100ms 이하 응답 필요. 파운데이션 모델은 수 초 소요. 결정론적이고 빠른 전통 ML이 적합. 생성형 AI는 해석·보고·고객 커뮤니케이션에 최적.

제조 AI — 3가지 핵심 사용 사례

제조 환경에서는 센서, 카메라, 운영 시스템으로부터 지속적인 데이터 흐름이 생성됩니다.

  • 예측 유지 보수(Predictive Maintenance): 진동·온도·압력 데이터 분석으로 고장 전 예측. Amazon SageMaker AI.
  • 시각적 품질 검사(Visual Quality Inspection): 카메라로 결함 실시간 감지. Amazon Rekognition + SageMaker AI.
  • 운영 인텔리전스(Operational Intelligence): 자연어 쿼리로 여러 시스템 데이터 통합. Amazon Bedrock + Bedrock Agents.
신뢰도 임곗값 트레이드오프

거짓 양성(False Positive) = 정상 제품 폐기 (비용 증가). 거짓 음성(False Negative) = 결함 제품 출하 (품질 리스크). 임곗값 조정이 핵심 설계 결정.

사용 사례
결정
비즈니스 가치(Business Value) 측정 가능한 KPI 결과

비용 절감·수익 증대·만족도 향상·프로세스 가속화. 구체적 KPI 미정의 시 배포 후 정당화 어려움.

KPI 측정 ROI 정의
기술적 타당성(Technical Feasibility) 생성형 AI 강점에 부합하는가?

요약·생성·대화·멀티모달 처리에 적합. 모든 문제에 생성형 AI 불필요. 기존 ML이 더 적합할 수도.

적합성 검토 역량 매핑
데이터 준비 상태(Data Readiness) 양보다 품질

데이터 품질 지식 소스
책임 있는 AI 조정(Responsible AI) 의무적 평가 — 선택 사항 아님

공정성·안전성·거버넌스 8차원 평가. 위험 수준에 따른 검토 강도 조정. 출시 후 체크리스트 아님.

8차원 평가 위험 분류
4가지 차원 모두 동시에 평가해야 합니다. 하나라도 미충족 시 재검토 필요.
4차원 평가 프레임워크

각 차원을 독립적으로 평가할 수 없습니다. 하나라도 미충족 시 전체 재검토가 필요합니다.

  • 비즈니스 가치(Business Value): KPI 측정 가능한 결과. ROI 정의 선행.
  • 기술적 타당성(Technical Feasibility): 생성형 AI 강점(요약·생성·대화·멀티모달)과 부합 여부.
  • 데이터 준비 상태(Data Readiness): 양보다 품질. 체계적 지식 소스 필수.
  • 책임 있는 AI 조정(Responsible AI Alignment): 8차원 평가. 의무적 평가 — 선택 사항 아님.
주의사항

4가지 차원은 독립 평가 불가. 하나라도 미충족 시 전체 재검토. 비즈니스 가치가 높아도 데이터 준비가 안 되면 진행 불가.

  • 공정성(Fairness): 성별·연령·인종 등 보호 속성에 따른 차별 없이 공정한 결과 제공
  • 설명 가능성(Explainability): AI 결정의 근거를 이해 가능한 방식으로 설명할 수 있는 능력
  • 안전성(Safety): 유해한 출력이나 결과로부터 사용자와 사회를 보호
  • 투명성(Transparency): AI 사용 사실, 모델 특성, 한계를 이해관계자에게 공개
  • 개인정보보호/보안(Privacy & Security): 개인 데이터 보호 및 무단 접근 방지
  • 제어 가능성(Controllability): AI 동작을 인간이 모니터링·수정·중단할 수 있는 능력
  • 진실성/견고성(Veracity & Robustness): 정확한 정보 제공 및 의도적 공격·입력 조작에 대한 저항성
  • 거버넌스(Governance): AI 사용에 관한 정책, 프로세스, 책임 소재 체계
HR 채용 AI 예시 — 평가 결론

HR 채용 보조 AI는 재설계 후 진행 판정. 주요 이유: 공정성(편향 위험), 설명 가능성(결정 근거), 개인정보(민감 정보) 이슈 해결 필요.

EU AI Act에서 채용 AI는 고위험 AI로 분류되어 강화된 투명성·감사 의무가 적용됩니다.

사용 사례: 저위험 vs 고위험 비교

저위험 — 내부 회의 요약 AI: 표준 평가, 경량 가드레일, 인적 감독 선택. 고위험 — HR 채용 AI: 강화된 편향 테스트, 설명 출력, 법무 검토, 감사 로그 의무화.

A멀티모달 모델은 입력에서 허용되는 것과 동일한 모달리티로 출력을 생성해야 하기 때문에 모델에 결함이 있습니다.
B모델은 추가 훈련 데이터가 제공되면 향후 버전에서 자동으로 이미지를 생성합니다.
C모델은 텍스트 및 이미지를 이해할 수 있지만 이미지를 생성할 수는 없습니다. 이해와 생성은 별개의 기능입니다. ✓
D모델은 텍스트 및 이미지를 이해할 수 있으며 구체적으로 요청하면 이미지를 생성할 수도 있습니다.
멀티모달 AI에 대한 가장 흔한 오해 중 하나는 1가지 유형의 콘텐츠를 이해할 수 있는 모델이라면 해당 유형의 콘텐츠를 생성할 수도 있다고 가정하는 것입니다. 실제로 입력 모달리티(Input Modality)와 출력 모달리티(Output Modality)는 모델마다 다른 별개의 기능입니다.
정답 해설 — 지식 확인 1

정답은 C입니다. 멀티모달 AI의 가장 흔한 오해: 1가지 유형의 콘텐츠를 이해할 수 있는 모델이라면 해당 유형의 콘텐츠를 생성할 수도 있다고 가정하는 것입니다.

핵심 원칙

이해(Understanding)와 생성(Generation)은 별개의 엔지니어링 기능입니다. Claude 3.5 Sonnet은 이미지를 이해하지만 이미지를 생성할 수 없습니다. Titan Image Generator는 이미지를 생성하지만 복잡한 이해는 불가합니다.

A실시간 사기 행위 탐지는 신속한 대응을 위해 생성형 AI를 사용하고, 사기 행위 사후 분석은 심층 분석을 위해 기존 ML을 사용합니다.

C사기 행위 탐지 및 사후 분석 모두 동일한 생성형 AI 모델을 사용합니다. 차이점은 처리된 트랜잭션의 양에만 있습니다.
D실시간 사기 행위 탐지는 지연 시간이 짧은 결정론적 채점을 위해 목적별 ML 서비스를 사용하고, 사기 행위 사후 분석은 내러티브 보고 및 패턴 요약을 위해 생성형 AI를 사용합니다. ✓
목적별 ML 서비스(Amazon SageMaker, AutoGluon 등)는 짧은 지연 시간과 높은 결정성으로 실시간 사기 행위 탐지를 처리합니다. 사기 행위가 탐지되면 생성형 AI(Amazon Bedrock, Bedrock Agents)가 패턴 요약, 내러티브 조사 보고서 작성, 규제 당국 제출 문서 초안 작성 등 사후 분석을 지원합니다.
정답 해설 — 지식 확인 2

정답은 D입니다. 핵심 구분: 목적별 ML(Purpose-built ML)은 낮은 지연 시간과 높은 결정성으로 실시간 채점. 생성형 AI(Generative AI)는 사후 분석에서 내러티브 보고서와 패턴 요약 생성.

실제 적용

Amazon SageMaker, AutoGluon: 실시간 사기 탐지. Amazon Bedrock, Bedrock Agents: 사후 분석·규제 문서·고객 서비스. 각 도구를 강점에 맞게 사용하는 것이 핵심.
